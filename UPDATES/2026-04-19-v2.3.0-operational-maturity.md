## New Skills (3)

### Systematic Debugging
`Council Chamber/Skills/Systematic Debugging/SKILL.md`

Four-phase root cause protocol for any technical issue. The Iron Law: no fixes without root cause investigation first. Phases: Root Cause Investigation, Pattern Analysis, Hypothesis and Testing, Implementation. Includes rationalization table (common excuses and their realities), red flags list, and escalation gate (3 failed fixes = architectural question, not a fourth fix).

### Plan Challenger
`Council Chamber/Skills/Plan Challenger/SKILL.md`

Adversarial pre-build pass on Pending Plans. Five structured angles: Strategic Fit, Timing, Baked-In Assumptions, Architectural Risk, Opportunity Cost. Taste-decision surfacing for near-call questions. One-line verdict (Proceed / Revise / Pause). Optional confidence scoring rubric (0-100) for high-stakes plans. Integrates with Pending Plan Implementation as an opt-in at the pre-execution checklist.

### Source Harvest
`Council Chamber/Skills/Source Harvest/SKILL.md`

Systematic pattern extraction from any external repo or tool. Four-disposition classification: Adopt (new capability), Enrich (strengthens existing), Defer (useful but no immediate gap), Ignore (already covered). Twelve-step process from access verification through approval gate to execution and registry housekeeping. Includes tool scoping pattern for permission boundaries.

## Protocol Upgrades (2)

### Pending Plan Implementation Protocol (v0.1 to v1.0)
`Council Chamber/Protocols/Planning/Pending Plan Implementation Protocol.md`

Major upgrade:
- **Re-entry fields required** for multi-session plans (was optional). Current State, Decision Point, Next Move, Re-Entry Context must be populated before execution begins in subsequent sessions.
- **Gate notation** added for plans spanning 3+ sessions. Structured format with scope, entry/exit conditions, status tracking, handoff notes.
- **Session Boundary Close Block** required at the end of each execution run within a gate. The re-entry anchor for the next session.
- **Organic completion check** added to Step 1. Scan for work that has already been delivered organically before committing to formal gate execution.
- **Archival pattern** detailed: move the plan file, then edit in place. Do not write a new copy and delete the original.
- **Support files policy review** added to archival step.
- **Plan Note Templates** added: Tier 1 (Focused Plan) and Tier 2 (Arc Plan) with frontmatter and required sections.
- Status lifecycle hardened with explicit rules for proposed, active, complete, archived transitions.

## Trust Anchor Hardening (4 New Sections)

`.claude/CLAUDE.md`

### Expression Standards
Rules for all generated content: no Oxford comma, no em dashes (absolute, no exceptions), positive framing, short declarative sentences, one idea per paragraph. Includes high-velocity drift guard. These violations are most likely in execution-dense sessions.

### External Publishing Confirmation
Three-state verification gate: Local, Submitted, Confirmed. Five-step verification function (Identify, Run, Read, Verify, Claim). No publishing task is complete until all three states are confirmed. Lists common rationalizations that bypass the gate.

### Operational Efficiency
Model routing defaults (Haiku/Sonnet/Opus), task complexity signals for subagent dispatch, MCP context budget (10 or fewer active), exploration efficiency rules (tool-to-scope matching), verification loop patterns (pass@k vs pass^k).

### Systematic Debugging Mandate
Standing instruction linking to the new Systematic Debugging skill. Any technical issue triggers the skill before any fix is proposed.
