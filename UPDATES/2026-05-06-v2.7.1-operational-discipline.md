## What This Is

The CLAUDE.md trust anchor accumulates operational discipline across Operational Efficiency and Planning and Execution. Six sub-rules added to Operational Efficiency (ad-hoc dispatch posture, expanded MCP context budget with hygiene rule, Database MCP security defaults, CLI vs MCP routing, parallel file-edit batching, Infrastructure-first principle). One new section (Planning and Execution) lands three rules: plan verification before handoff, move audit rule, and an explicit reference to the Pending Plan status vocabulary already defined in the Implementation Protocol.

These are universal token-efficiency and infrastructure-discipline rules. None are Sovereign-specific.

## What It Adds / Changes

**Operational Efficiency additions:**
- **Ad-hoc dispatch posture.** For unplanned mid-session work the standing question fires: would Sonnet or Haiku yield equivalent output here, with fewer tokens? Default-Opus inheritance is not the answer. The discipline is the asking, not a hard rule.
- **MCP context budget hygiene rule.** Deactivate any MCP that is broken for one session, unauthenticated for one session or unused for thirty days. Adding a new MCP requires removing or deferring an existing one of equivalent or greater context cost. Tool-schema breadth (not server count alone) drives the per-dispatch floor.
- **Database MCP security defaults.** Three controls applied at configuration time: scope to a single project (`project_ref=<id>`), enable read-only mode (`read_only=true`), restrict tool groups via the `features` allowlist.
- **CLI vs MCP routing.** When both a CLI and an MCP exist for a service, prefer the MCP. CLI device-auth flows can leak browser popups if processes orphan between sessions; MCP tool calls leave a cleaner audit trail.
- **Parallel file-edit batching.** When applying the same rule across N similar files, batch Reads in one message and batch Edits in one message. Twelve files = twelve Reads in parallel, then twelve Edits in parallel. Sequential round-trips waste tokens. Exception: edits with content-conditional logic stay sequential.
- **Infrastructure-first principle.** When a required tool, MCP, script or integration is broken or missing, the default is to fix the infrastructure. Not to propose a manual workaround. Manual copy-paste packets and "fall back to the web UI" are the patterns this rule prevents. Exception: if the infrastructure does not exist yet, build it (preferred for reusable work) or scope it as an explicit blocker.

**New Planning and Execution section:**
- **Plan verification before handoff.** Any implementation plan that hands subagents substantive code blocks (CSS, config, components) must be build-verified against the target environment by the plan author before dispatch. Inline code in a plan is not verified code. Unverified blocks are flagged as drafts.
- **Move audit rule.** When a canonical file is relocated (any path change beyond a simple rename in place), the move is not complete until a full-vault wikilink grep for the old path has been run and every active reference updated. Stale wikilinks from prior moves are a recurring defect class. The move and the sweep are one unit of work.
- **Pending Plan status vocabulary reference.** Status follows the four-state ladder defined in the Pending Plan Implementation Protocol: `proposed → active → complete → archived`. Status advances only one direction.

## How to Implement

1. **Pull the new `.claude/CLAUDE.md`.** Diff your existing CLAUDE.md against this version. Most additions land inside the existing Operational Efficiency section; the Planning and Execution section is new.

2. **Audit your active MCPs against the hygiene rule.** Are any broken, unauthenticated, or unused for 30+ days? Deactivate them. Adding a new MCP from this point requires removing or deferring an existing one of equivalent or greater context cost.

3. **Audit your database-adjacent MCPs against the security defaults.** If you have any database MCP configured, confirm it is scoped to a single project, set to read-only, and uses the `features` allowlist. Apply the three controls now. Configuration time is cheaper than incident time.

4. **Adopt the parallel batching pattern.** When your AI is about to do the same edit across multiple files, the right shape is one parallel-Read message followed by one parallel-Edit message. Not Read-Edit pairs in sequence.

5. **Apply the move audit rule on the next file relocation.** When you (or your AI) move any canonical file, the close of work is not the move itself. It is the wikilink grep across the vault and the update of every stale reference. Treat it as one unit.

Foundation build complete. CLAUDE.md template active.
