## What This Is

One new script, one command for you to run, and a round of corrections that bring the install guides back in line with the platforms they describe.

**If you installed any earlier version, run this once from your vault root:**

```
node "Council Chamber/scripts/link-skills.mjs"
```

That is the whole action. It links every skill in `Council Chamber/Skills/` into `.claude/skills/`, so your AI interface can invoke them as slash commands. Using Codex? Add `--codex`. Safe to run any number of times, and it reports what it did.

## Why

The Foundation has always shipped its skills, and they have always arrived unreachable. A link is a local filesystem object that git and a ZIP download do not carry, so every fresh install landed with a full shelf of skills the interface could never discover. The repo's own CI carried the sentence for this state before the fix existed: present, and unreachable.

Session 1 told the reader to create the links by hand, one command per skill. On a fresh install that instruction failed, because the parent folder `.claude/skills/` does not ship either, and the command it recommended assumed it was there. The instruction also asked for administrator rights it never needed and, on Mac, wrote a relative link that pointed at nothing.

The second half of this release is about drift of a different kind. The install guides made claims about other people's platforms, and the platforms moved:

- The guides offered the free Anthropic tier as a way to run the coding interface. That path no longer exists. Claude Code requires Pro or higher, or API credits. A reader following the old guide hit a wall at the login step with no explanation.
- The guides pointed the desktop-app download at a URL that now opens the web app, with nothing to download. The desktop app lives at claude.com/download, and Claude Code is its Code tab.
- README and BOOTSTRAP disagreed with the public library and with each other about how many skills it holds. The live registry says 27 skills and 7 bundles, and both files now say what it says.

## What Changed

- **New: `Council Chamber/scripts/link-skills.mjs`.** Links every canonical skill into the interface adapter directory in one pass. Junctions on Windows, which need no administrator rights. Symlinks on Mac and Linux. Idempotent, self-reporting, and it repairs broken links in place. It is the creating half of the shipped `check-skill-mirrors.mjs`, which remains the verifying half.
- **New: `Council Chamber/scripts/link-skills-selftest.mjs`.** The positive control. Five cases: creation, idempotence, agreement with the drift checker, repair of a broken link and the loud failure on a vault with no skills. Per the standing law, a guard ships with the test that proves it, and CI fires both on every push.
- **Session 1, Step 3** now runs the script instead of walking the reader through per-skill link commands. The manual path stays as a documented alternative, corrected to create the parent folder first and to write links that resolve.
- **BOOTSTRAP** links the skills during platform setup, so wizard users get working slash commands without meeting the step at all.
- **Quick Start Guide and Session 0** now state the real cost of entry (Claude Pro or higher, the free account covers the chat website only), point the desktop-app path at claude.com/download and name the Code tab. The Quick Start's Common Issues section gains the upgrade-prompt entry for the wall readers were hitting.
- **`.github/workflows/verify.yml`** gains two steps: the linker's positive control, and an end-to-end pass that links the real checkout and then requires the drift checker to call the result clean.
- **`scripts/framework-manifest.json`** classifies the new pair as framework, and picks up the mirror-checker pair that had shipped unclassified.

## The Spec, If Your Copy Has Diverged

Your vault may have renamed folders or moved skills. The intent, independent of any diff:

1. Every directory under your canonical skills folder that contains a `SKILL.md` should be reachable through your interface's skill directory (`.claude/skills/<Name>/SKILL.md` for Claude Code).
2. The links should be filesystem links rather than copies, so the canonical file stays the single source of truth.
3. The state is verified, not assumed: `node "Council Chamber/scripts/check-skill-mirrors.mjs"` exits 0 when every skill is reachable and nothing has drifted.

## The Test

After running the linker:

```
node "Council Chamber/scripts/check-skill-mirrors.mjs"
node "Council Chamber/scripts/link-skills-selftest.mjs"
```

The first proves your vault's skills are reachable. The second proves the tool itself still creates, repeats, repairs and refuses exactly as specified.
