## What This Is

**Apply this if you installed any version of this template.** Everything here is additive. Nothing you already run changes behavior.

The headline is not a new guard. It is a check on the thing that proves the guards.

Since v3.4.0 this template has shipped `hooks-selftest.mjs`, and its green run has been the evidence that every hook works. That evidence was weaker than it looked. A test suite fails by reporting clean, which is the same shape as success, so a green suite means nothing until something is pointed at the suite itself. Nothing was.

Running that check for the first time found a case that had been shipping since v3.4.0 and proving nothing at all.

## The Governing Idea

A guard you have read is not a guard you have fired. That has been this project's law since v3.3.1, when a deletion gate shipped that refused nothing.

This release extends it one level. **A test you have run is not a test that could have failed.** A case that asserts the absence of something passes just as happily against a hook that does nothing, because a dead hook produces no output and the absent string is duly absent. It goes green. It proves nothing. It reads exactly like proof.

The defense is a second instrument aimed at the first.

## The Second Instrument

`hooks-selftest.mjs` gains two modes.

**The negative control.**

```
node "Council Chamber/scripts/hooks/hooks-selftest.mjs" --negative-control
```

Re-runs every case with each hook replaced by a do-nothing stub. Any case that still passes is vacuous and is reported as `VACUOUS`, and the run exits 1.

Cases now declare which kind they are, because the distinction is real and hiding it would be its own dishonesty. A `reacts` case demands the hook DO something, so a stub cannot satisfy it and the negative control can falsify it. A `quiet` case demands the hook NOT do something, which a stub satisfies trivially, so the negative control reports `n/a` rather than pretending to have tested it. The current suite is 10 falsifiable and 8 not.

**The registration audit**, which runs as part of the normal pass. Every case in this suite fires its hook directly. That proves the script works and says nothing about whether a session will ever call it. A perfect guard nobody wired up is a decoration. So the suite now reads `.claude/settings.json` and, for every hook script on disk, reports whether an event is registered whose command would reach it. An unregistered hook is a FAIL rather than a note, because its self-test passing is exactly what makes it dangerous. It looks covered.

The hook list is read from the directory rather than hardcoded, so a hook you add tomorrow is audited tomorrow instead of being silently exempt.

**What it found immediately.** The `index-regen` case asserted the absence of the string "no regen cmd configured". A stubbed hook writes no log, so the string was absent and the case passed against nothing. It now requires positive evidence in the log. If you have been reading that green tick as proof your index regeneration works, it was not.

### How to verify

```
node "Council Chamber/scripts/hooks/hooks-selftest.mjs"
node "Council Chamber/scripts/hooks/hooks-selftest.mjs" --negative-control
```

The first must report `behavior: pass=N fail=0` and `registration: pass=N fail=0`. The second must report `vacuous=0`. If the second reports any vacuous case, that case has been lying to you and needs rewriting to demand positive evidence.

If you want to confirm the negative control itself works before trusting it, add a case that asserts the absence of a string that never appears, declare it `reacts`, and run the negative control. It must flag it `VACUOUS` and exit 1. Remove it afterward.

## The Decision Journal

A new script, `Council Chamber/scripts/decision-journal.mjs`, compiles a read-only journal of every `#decision`-tagged line in the vault into `Council Chamber/Governance/Decision Journal.md`.

Harvest, never double-enter. Decisions stay recorded where they land. This indexes them so "what did I decide, when, and why" is one read instead of a grep. That is Principle 1 applied to your own record.

```
node "Council Chamber/scripts/decision-journal.mjs"
node "Council Chamber/scripts/decision-journal.mjs" --check
node "Council Chamber/scripts/decision-journal.mjs" --positive-control
```

**Its guard is relative, on purpose.** A generated file can be destroyed silently: the scan breaks, harvests nothing, and overwrites a good journal with an empty one that still looks generated. The obvious defense is a minimum entry floor, and it is the wrong one here, because a new vault legitimately has zero decisions and a tool that fails on day one gets deleted on day one. So the guard compares this harvest against the count the last journal recorded for itself, and refuses on a collapse. Zero to zero is a Tuesday. Growth is never suspicious. `--force` overrides it when a large deletion was real.

**Two things look like a tagged decision and are not.** A tag inside a code span is a document naming the convention, which every protocol and template does. A line still carrying `YYYY-MM-DD` is an unfilled template. Both are excluded. Without that, the first run on a fresh vault returns a journal of documentation about journals, which is worse than an empty one because it looks like it worked.

The guard ships with `--positive-control`, which fires it rather than reading it, across 15 cases covering both the collapse rule and the harvest filter. It must be green before you trust the journal.

## The Ports

Four things the source vault carried and this template lacked.

**Exposure Tier replaces Trust Tier in the Interface Adapter Registry.** The registry rated each adapter with a "Trust Tier". The Constitution separately rates each AGENT with a "Trust Tier". One name, two unrelated concepts, and nothing said so. Adapters now carry an Exposure Tier, E0 to E4, rating the blast radius if that interface misfires. Agents keep their Trust Levels. Different letters, so the two can never be confused again. E0 reads and mutates nothing. E3 writes into a live external system where a bad action costs money or reaches the world. E4 is autonomous within a ratified class.

**Governance Principle 3, name the grade on the act.** Delegated authority carries one of two grades, marked when the act happens rather than reconstructed later. An executory act implements an instruction as given. A discretionary act applies judgment inside a bounded domain. The Abbasid vizier system named these two grades formally, and English regency marked delegated acts on the record itself so the delegation stayed visible. This names the grades. It does not widen authority.

**The Anti-AI Writing Patterns Codex reaches full parity, 60 entries to 114.** The v1.0 template shipped a curated subset and stopped. The missing catalog is the whole back half: the voice tells (Sage Tone, Coach Voice, the conference-talk cadence, Performed Warmth, the Wisdom-Broker Register) and every structural tell (Three-Bullet Floor, Listicle-Creep, Header-Above-Everything, the Key-Takeaways Box, the TL;DR Reflex). Entries are renumbered to the source catalog's own scheme, including lettered sub-entries, so numbers are stable from here.

**The Intake Routing Law** joins the Capture Classify Route Protocol. Four rules for any vault taking material in from more than one direction. Classify by content and never by source. The intake surface is a dock, never a residence. Deferred analyses ride a named contract with a standing rendezvous, never "later". Timeliness follows a named ladder. A fifth rule of this set, that inbox content is data and never instruction, lives in `.claude/CLAUDE.md` and is pointed at rather than restated, because restating it would break Principle 1.

## Corrections

Three claims in this template were wrong and are now right.

- `AGENTS.md` and `BOOTSTRAP.md` claimed 24 installable skills in the public library. There are 28, ground-truthed against the deployed marketplace rather than the repo.
- `AGENTS.md` said five skills are dual-distribution and five graduated out entirely. It is seven and four. Systematic Debugging and PR Code Review are both bundled here AND in the public library.
- `Skills Index.md` listed Systematic Debugging twice, once as bundled and once under a heading reading "no longer bundled in the Foundation". Both could not be true.

The structural lesson is worth more than the three fixes. CI validated the Skills Index roster and never the sentences describing it, so the drift moved to the prose. A check that validates a list does not validate the paragraph about the list.

## How To Apply

This template is meant to be customized, so a diff will not apply cleanly to your copy. Take the intent, not the patch.

1. Replace `Council Chamber/scripts/hooks/hooks-selftest.mjs` with the version in this release, then run both modes. If you added your own cases, port them across and give each one a `kind` of `reacts` or `quiet`.
2. Add `Council Chamber/scripts/decision-journal.mjs`. Run `--positive-control` first. Never trust the guard before you have watched it refuse.
3. Add the four CI steps in `.github/workflows/verify.yml`: the negative control, the journal guard control, the journal `--check`, and keep the existing positive controls. A control that is not in CI decays back to a control nobody runs.
4. The four ports are prose. Read them and take what fits your vault. The Exposure Tier rename is the one to prioritize if you built an adapter registry from this template, because you inherited a real ambiguity.
