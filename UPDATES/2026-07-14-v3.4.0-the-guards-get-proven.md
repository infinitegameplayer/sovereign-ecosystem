## What This Is

v3.3.1 fixed one guard that had never been fired. This release fired **all of them**, and found that three more were broken.

**Apply this if you installed any version of this template.** None of these is a hole an attacker walks through. Each one is an instrument you have been trusting that was reporting success while doing nothing, which is its own kind of unsafe.

## The Question That Found Them

After v3.3.1, the obvious question was whether the deletion guard was the only one that had shipped unproven. Six other hooks had never been fired either. They had been read, reviewed and shipped, exactly like the one that turned out to be broken.

So they were fired. Three of the six were defective, and every defect was silent.

## What Was Broken

**`post-write-index-regen.sh` could never regenerate anything.** It shipped with both regen commands set to empty strings and no regen script anywhere in the repo to point them at. On every write it logged `trigger detected (no regen cmd configured)` and did nothing. Forever. It read as protective and was structurally incapable of acting.

The cost was already on the shelf: **the Ecosystem Update Check skill was missing from the Skills Index.** Present on disk, absent from the catalog, therefore invisible to the AI interface that reads the catalog to know what it can do. A skill you shipped, that your agent could never find. That is precisely the drift the hook is named for, and the hook watched it happen and logged that it noticed.

**`post-write-em-dash-check.sh` failed in both directions at once.** Its vault-scope check was a case-sensitive string prefix match. On Windows the same file arrives as `C:/vault/x.md` or `c:/vault/x.md` depending on which tool hands it over, and nothing guarantees the casing. A drive-letter mismatch made the comparison fail, and the hook exited before ever reading the file: no warning, no log, no trace. **The gate went dark and looked healthy doing it.** Separately, with `SOVEREIGN_VAULT_ROOT` unset it skipped the scope check entirely and warned on any Markdown file anywhere on the disk. Too narrow and too wide, in the same twelve lines.

**The two compact hooks wrote and read different paths.** `pre-compact-state-capture.sh` resolved `.runtime` against the working directory rather than the vault. Fired from a subdirectory it planted an orphaned `.runtime` there, and the snapshot `post-compact-reorienter.sh` later looked for at the vault root was never written. The capture reported success. The state was gone. The reorienter said "no pre-compact state found", which is indistinguishable from a session that had nothing to reorient.

**Clean under every input tried:** `pre-write-floor-guard.sh` and `session-start-primer.sh`. They do what they claim.

## What This Release Adds

**`Council Chamber/scripts/hooks/hooks-selftest.mjs`.** The positive control for every hook except the Floor gate, which has its own. Twelve cases. Each hook must react to what it must react to **and stay quiet otherwise**, because a hook that fires on everything has become a wall, and a wall is also a failure.

It carries a regression test per defect, including the lowercase drive letter that once made the em dash gate go dark.

```sh
node "Council Chamber/scripts/hooks/hooks-selftest.mjs"
```

Point it at the pre-fix hooks and it reports `pass=7 fail=5`. Point it at the fixed hooks and it reports `pass=12 fail=0`. **It has been watched failing.** That is the only thing that makes a pass from it mean anything.

**`.github/workflows/verify.yml`.** This repo had **no CI at all.** Nothing verified it on any push, ever, which is the reason a guard that refused nothing could ship and sit there. Now every push and every pull request fires both self-tests against a fresh checkout, with `SOVEREIGN_VAULT_ROOT` unset, which is the state you are actually in when you clone.

It also runs weekly on a schedule, whether or not anyone pushed. A guard rots unobserved, and "it was green last week" is the exact condition under which it rots.

**`Council Chamber/scripts/build-skills-index.mjs`.** The regen script the index hook was always supposed to call. It rebuilds the roster from your SKILL.md frontmatter and **preserves everything a human wrote**: your curated descriptions, your manual sections below the roster. Run it with `--check` and it names any skill that is on disk and missing from the Index, or in the Index and gone from disk.

A note on its own first bug, because it is the lesson of this release in miniature. The first cut defaulted a skill with no `tier:` field to `operational`, and quietly demoted two skills a human had deliberately curated as `foundational`. **A generator that invents a value where its source said nothing is not regenerating an index. It is overwriting knowledge with a guess.** Absence of data is not data. It now preserves the existing value when frontmatter is silent.

## The Governing Law

**Nothing that guards may ship without its positive control.**

A guard travels with the test that proves it refuses. Not the test that proves it compiles, or that it runs, or that it exits zero. The test that proves it **refuses what it claims to refuse and permits what it claims to permit**.

The corollary, learned twice now at our own expense:

> **A guard with no positive control is not a feature. It is a liability with good intentions**, because you trust it more than you would have trusted nothing at all.

Ask it of every ceiling you own: does this **refuse**, or does it merely **not-happen**? An empty log is the same shape whether the guard is working perfectly or has been dead for a month.

## How to Implement

1. Replace the four fixed hooks in `Council Chamber/scripts/hooks/`.
2. Add `hooks-selftest.mjs` and `Council Chamber/scripts/build-skills-index.mjs`.
3. Add `.github/workflows/verify.yml`.
4. Update `.claude/settings.json`: the two compact hooks now receive `SOVEREIGN_VAULT_ROOT` like every other hook. They were the only two that did not.
5. Run both self-tests from your vault root:
   ```sh
   node "Council Chamber/scripts/hooks/floor-gate-selftest.mjs"   # expect pass=21 fail=0
   node "Council Chamber/scripts/hooks/hooks-selftest.mjs"        # expect pass=12 fail=0
   ```
6. Run `node "Council Chamber/scripts/build-skills-index.mjs" --check`. If it names a skill missing from your Index, run it without `--check`.

If step 5 is not green, your guards are not protecting you, and the failing lines say exactly which one is asleep.

## If You Customized Your Hooks

Your copy is yours. **Do not take this diff. Take the tests.**

Drop `hooks-selftest.mjs` and `floor-gate-selftest.mjs` into your vault and run them against your own hooks. The thirty-three cases are the spec. How your hooks satisfy them is your business, and the intent travels even when the code will not.

That is what a sovereign update looks like. You own your code. The standard is what ships.
