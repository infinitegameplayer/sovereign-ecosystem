## What This Is

A doctrine prune. The Object Model declared nine object classes. It now declares five.

`Spark`, `Insight`, `Experiment` and `Rule` are retired. `Quest`, `Artifact`, `Brief`, `PendingPlan` and `InboxItem` stay.

**Nothing breaks if you ignore this.** No script reads these classes, no hook enforces them and no guard changed. If you have been using any of the four, keep using it. Read The Migration below and decide for yourself.

## Why

The four were declared in prose, described in prose and never mechanically used anywhere. That is provable from this repo alone: a grep for them in frontmatter or wikilinks returns zero across 245 files. They were concepts, never instances.

The stronger evidence comes from the one long-running installation of this template. Across months of real daily use it produced zero notes of all four classes, and retired them locally. A fresh clone has zero instances of everything, so that number alone proves nothing. What transfers is different and harder to argue with: **the author of these four classes did not use them.** Shipping them anyway hands every recipient four concepts their designer abandoned, and asks a new reader to spend attention deciding whether a note is a Spark or an Insight when the answer never once mattered.

This template already carries the rule it was breaking. `Council Chamber/Governance/Governance Principles.md`, Principle 2, Scaffolding proportionality: structure earns its mass by measured load, and instrumentation built ahead of a proven lane becomes overhead rather than leverage. Four classes with no instances is that principle's own example, sitting in the same repo as the principle.

There is a second cost specific to a template. A reader who cannot tell which parts of a governance system are load-bearing will treat all of it as load-bearing. Every unused class raises the price of the whole thing.

## What Changed

The four `##` sections are gone from the Object Model, and the Constitution's class list drops to five. Twenty-nine files carried references and all of them were reconciled. The two templates that existed only to instantiate a retired class are removed.

The Object Model gains one short closing section saying that five is a floor rather than a ceiling, and naming the condition under which adding a class is earned.

**A pre-existing drift surfaced while doing this and is fixed in passing.** The Constitution listed eight classes where the Object Model declared nine. `Brief` was missing from the Constitution and had been since the class was introduced. Two documents describing one model, disagreeing, with nothing checking them against each other.

## The Migration

**If you never used these four classes, there is nothing to do.** That is the expected case.

**If you have notes of these types**, nothing deletes them and nothing stops working. Pick one:

1. **Keep them.** Add the class back to your own Object Model. It is your vault, and a class you actually instantiate is a class that earns its place. This update is not an argument that these are bad ideas, only that they were unused ones.
2. **Fold them in.** The natural homes, if you want fewer classes:
   - `Spark` and `Insight` become `InboxItem` notes that stay in `Inbox/` for incubation, or graduate to a `Quest` when they acquire an outcome.
   - `Experiment` becomes a hypothesis/method/result block logged inside the `Quest` it belongs to. The `Quest` class already names experiments in its purpose.
   - `Rule` was always a description of what codices, protocols and the Constitution already do. Those documents are the rules.

**If your intake routes on a `spark:` prefix**, that prefix is gone from the Capture Classify Route Protocol and now falls to `InboxItem`. If your mobile capture depends on it, either keep the prefix in your own copy or retrain the habit to `inbox:`.

## Verify

There is no new guard here, so there is no new positive control. What there is instead is a check you can run against your own vault to confirm the prune is complete rather than half-done, which is the only way this update can hurt you.

From your vault root:

```sh
# Every remaining mention of the four classes, so you can read each one.
# Expect only ordinary English: "insight", "Self-Rule", "Classification Rule",
# "Three Solutions Rule", "Creative Spark", "what sparks".
grep -rInwE "Spark|Sparks|Insight|Insights|Experiment|Experiments" \
  --include="*.md" . | grep -v "^./UPDATES/" | grep -v "^./CHANGELOG.md"
```

**Read every hit. Do not trust the count.** `Rule` and `Insight` are ordinary English words, this repo contains a protocol named Three Solutions Rule, the Object Model has its own Classification Rule section and a flywheel is named Creative Spark. A bare grep returns dozens of files that are almost all false positives, and a frontmatter-and-wikilink grep returns zero, which tells you nothing about the prose. Pattern matching cannot do this job. Reading can.

The one mechanical check that is safe:

```sh
# The two retired templates should be gone.
ls "Council Chamber/Templates/Object Templates/"
# Expect: Inbox Intake Analysis Template.md, InboxItem.md, PendingPlan.md,
#         Quest.md, Session Summary.md
```

Then confirm nothing else moved:

```sh
node "Council Chamber/scripts/hooks/floor-gate-selftest.mjs"     # expect 29/0
node "Council Chamber/scripts/hooks/hooks-selftest.mjs"          # expect 18/0, 11/0
node "Council Chamber/scripts/build-skills-index.mjs" --check
```

## The Part Worth Keeping

The prune took one file. The reference sweep took twenty-nine, and the sweep was the whole job.

A retired class that stays named in a protocol is worse than one never retired, because the reader now meets a concept the system no longer defines and has no way to look it up. The removal and the sweep are one unit of work. Half of this update would have left the template worse than none of it.

The scope of this change was written down eight days before it ran, and it was wrong in both directions when re-derived. It named roughly ten affected files where the true number was twenty-nine, because the first survey used singular word boundaries and four protocol files referenced the plural. It named a governance file as carrying references that it does not carry, on a match that turned out to be a section heading called Structural Rule. **A scope is a claim, and it goes stale exactly like a status does.** Re-derive it from the question you are asking now rather than inheriting it.
