## What This Is

A repeatable concurrent audit method for reviewing the outputs of any completed phase before the next phase begins. Surfaces gaps, expression violations, unsupported claims and forward obligations while the foundation is fresh — before the next layer builds on top of it.

## What It Adds / Changes

- `Council Chamber/Protocols/Governance/Phase Audit Protocol.md` — new governance protocol defining when and how to run a Phase Audit
- Two-pass concurrent method: Claude Code Explore agent (structured checklist) run in parallel with a Gemini challenger pass
- Aggregation pattern: merge, classify (fix-in-session vs. defer), apply fixes, add breadcrumb to master plan
- Mandatory expression standard scan included in every audit pass
- Filing convention: findings go to master plan breadcrumbs and (if recurring) to the audited document's Refinements section

## How to Implement

1. Copy `Council Chamber/Protocols/Governance/Phase Audit Protocol.md` from this update into your vault.
2. Run a Phase Audit at the end of any multi-session phase sequence before a higher-stakes phase begins — architecture decisions, live builds, public launches.
3. Do not run for operational outputs, scripts, sync results or logs.
4. At the end of each audit, add a breadcrumb to your master plan: "Phase X Audit complete" with findings summary, fixes applied and deferred items tagged to their destination phase.

## Prerequisites

None. Works on any initialized Sovereign Ecosystem instance with a configured Gemini interface.

## Optional?

No. Catching foundation gaps before the next phase is cheaper than patching them after.
