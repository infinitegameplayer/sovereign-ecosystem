## What This Is

The major version. The template grows three new ways to begin, to stay current and to travel.

A fresh clone used to mean an hour of manual configuration before the first real session. Now it can mean fifteen minutes and one sentence. A clone used to be a snapshot frozen at download time. Now it is a living relationship with upstream you control file by file. The skills used to assume one AI tool. Now they run across the major agent platforms without a fork.

The template stays the spine. Everything here is an additive door. The full experience still lives in the vault you own. The plugin path is a second entrance for the curious, not a replacement for the home.

## What It Adds / Changes

### 1. BOOTSTRAP.md guided onboarding

A new self-deleting setup wizard at the repo root. Open your AI interface with this folder loaded and say "read BOOTSTRAP.md and run it." The interface runs a short interview, personalizes the vault from the answers, points you at your first session, then removes itself.

The flow:

- **Six questions, one at a time.** Your name, your AI interface name, your timezone, your vault path on disk, your primary platform and the governance depth you want to start with. Conversational, not a form dump. Each answer is reflected back so you know it landed.
- **Token substitution.** The wizard runs `scripts/replace-tokens.mjs`, the one-time substitution tool. It replaces the identity tokens across every `.md`, `.txt` and `.json` file in the vault. The script previews every change and waits for a typed `YES` before writing. The preview-then-confirm gate is a feature.
- **Platform-specific setup.** The platform answer routes the next move. Claude Code gets the two write-time hooks wired into `.claude/settings.json` using the vault path you gave. Cursor, Gemini CLI, Codex and other interfaces get pointed at the right governance anchor, with the hook wiring left as the Claude Code convenience it is.
- **Governance depth routing.** Light, Standard or Deep. The choice maps to which Getting Started sessions to open now and which to hold for later. The depth only sets where you begin. Nothing locks.
- **A completion note in `Primer.md`.** The wizard writes a short block recording the choices made, the timezone (which has no token) and the next session pointer.
- **Self-deletion.** Once you confirm the setup, the wizard deletes itself. A one-time door that removes itself when it has done its job.

A safety rail runs first. The wizard reads `.claude/CLAUDE.md` for the identity tokens before asking anything. If the tokens are already gone, the vault has been personalized, and the wizard stops cleanly rather than running again.

The Getting Started sessions remain the deep path, the one that builds real understanding session by session. The wizard gets you to a personalized, oriented starting line faster. The depth still lives in Getting Started, and the wizard hands you off to it at the end.

### 2. Versioned upgrade path

A clone is no longer frozen at download time. Three new pieces turn a one-time copy into a living relationship with upstream.

- **`scripts/se-update.mjs`.** The upgrade tool. It confirms an upstream remote, fetches the upstream default branch, diffs every file against your local HEAD and prints a categorized change list. Four modes:
  - `--check`: fetch upstream and print the categorized change list.
  - `--diff "<path>"`: show the diff for one file, both directions, so you can see local modifications and upstream changes together.
  - `--apply "<path>"`: apply the upstream version of one framework file and stage it.
  - `--force-seeded "<path>"`: apply an upstream change to a seeded file, overwriting your personalization. A door, not a default.
- **`scripts/framework-manifest.json`.** The path-classification authority. Every file falls into one of three classes.
  - **Framework.** Upstream-maintained. Offered for review and optional application. Safe to apply independently.
  - **Seeded.** Shipped once as a starting point, then yours. Informational by default. Applying an update overwrites your personalization, so it requires `--force-seeded` and an explicit decision. The Humor Codex, the Primer, the hook scripts and the To-Do Dock live here.
  - **User.** Files you created. Upstream does not own them and never touches them.
- **The Sovereign Sync skill** at `Council Chamber/Skills/Sovereign Sync/`. The conversational layer over the tool. It runs the check, presents the framework change list grouped by added, modified and removed, reads each file's description aloud for context, then mediates per-file approval. Apply, skip or defer, file by file. It bookends the sync with a single git commit whose body names what was applied, what was skipped and the upstream ref. Seeded files stay a separate explicit decision with a mandatory overwrite warning.

This is the structural heart of the release. The template was a one-time clone. It is now a framework you can keep current without losing a single thing you made your own.

### 3. Cross-platform SKILL.md compatibility pass

All 15 skills plus the Skill Template now carry agentskills.io-standard frontmatter and platform-portable instructions. Two changes per file:

- **Frontmatter.** A kebab-case `name` and an agent-routable `description` so any compliant agent can route to the skill by intent.
- **Instructions.** Platform-portable phrasing so the steps run without assuming a single tool.

The skills now run in Claude Code, Cursor, Gemini CLI, Codex and peer interfaces without a fork. One skill set, many doors.

### 4. Public library wave

Three Foundation skills now also ship as standalone installable plugins in the Infinite Game OS public library at infinitegameos.io.

- **Self-Healing**
- **Session Closeout**
- **Playwright**

This is dual-distribution. Each skill stays in the Foundation as part of the full experience and also installs as an individual plugin for anyone who wants that one door. Source Harvest has shipped this way since v2.4.0. These three join it. The template remains the complete system. The plugins are individual entrances for people who want a piece before the whole.

## How to Implement

### BOOTSTRAP (fresh clones)

1. On a fresh clone, open your AI interface with the folder loaded and say "read BOOTSTRAP.md and run it." Follow the interview. The wizard handles the rest and removes itself at the end.

2. On an existing personalized vault, you do not run BOOTSTRAP. The wizard detects a personalized vault by the absent identity tokens and stops cleanly. The file is already absent on a vault that ran it, since it self-deletes. If it is present and you are personalized, you may remove it by hand or leave it.

### The upgrade path (existing installations)

1. Pull the three new files: `scripts/se-update.mjs`, `scripts/framework-manifest.json` and the `Council Chamber/Skills/Sovereign Sync/` skill.

2. Configure an upstream remote pointing at the Sovereign Ecosystem repo if you have not already. Running `node scripts/se-update.mjs --check` without one prints the exact command to add it.

3. Run a first sync through the skill. Invoke Sovereign Sync. It walks the check, the per-file review and the commit:

   - `node scripts/se-update.mjs --check` lists what changed upstream.
   - `node scripts/se-update.mjs --diff "<path>"` shows any single file before you decide.
   - `node scripts/se-update.mjs --apply "<path>"` applies and stages one approved framework file.
   - `node scripts/se-update.mjs --force-seeded "<path>"` is the separate, explicit path for a seeded file, with the overwrite understood.

4. Commit the sync. One commit, body naming applied, skipped and the upstream ref. The commit is the sync record.

### The cross-platform skills

1. The skill frontmatter and instructions update in place when you apply the skill files through Sovereign Sync or pull them directly. No separate step.

2. If you run an interface other than Claude Code, the updated frontmatter and portable instructions are what let your interface route to and run each skill. Confirm your interface reads `name` and `description` frontmatter for routing.

### The public library plugins

1. Nothing to do inside the vault. Self-Healing, Session Closeout and Playwright stay in your Foundation exactly as before.

2. If you want any of the three as a standalone plugin in another context, install it from its page at infinitegameos.io. The plugin and the Foundation copy are the same skill through two doors.

## Optional?

No for the core surfaces. These all ship to the template as core: BOOTSTRAP.md, the README Fast Start, the upgrade path scripts, the Sovereign Sync skill and the cross-platform skill frontmatter.

The upgrade path is only as active as your upstream remote. Configure the remote to use it, and the template becomes a framework you keep current. Leave it unconfigured and nothing changes; the script prints the one-line fix when you are ready.

The public library plugins are optional by nature. Your Foundation already carries all three skills. The plugins exist for installing a single skill into another context, not for adding anything to the vault you already hold.
