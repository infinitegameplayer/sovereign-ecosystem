## What This Is

A harvest release. Five clusters of operating pattern that proved themselves in a working vault, now folded back into the template. One doctrine pass on the trust anchor. One status-ladder migration across every planning surface. The Humor Codex graduates from placeholder to seeded starter. The Autonomous Improvement menu deepens from a short inline list to a full external catalog. Two new write-time hooks land.

Nothing here is new architecture. It is the template observing its own maturity. Each item started as a pattern lived in real use, earned its keep and earned a home in the shipped Foundation.

## What It Adds / Changes

### 1. CLAUDE.md doctrine pass

Five operating rules join the trust anchor.

**Claim Integrity.** The parent verification rule. A claim's truth is verified at the moment the claim is made, not assumed from a visible surface. It carries three faces, each one a known drift point:

- **Relocation.** A move is verified by a full link sweep for the old path, not by the edit landing.
- **Fact.** A fact change is verified against the canonical artifact, not the surface that propagates it.
- **Delivery.** A publish is verified end to end to the human, not at the instrument level.

The shared failure mode is a state reported true that holds on one surface and fails on the rest. Future drift gets named as another face of this one class, then verified where it is asserted.

**Flywheel Check.** A Session Calibration discipline. When an action sets or changes a pattern, standard or surface that later work could overwrite, ask how it connects to the larger system and whether it warrants a durability upgrade, a canonical home or an enforcement hook. Most checks fire and pass unanswered. The discipline is the asking. Trigger words: replicate, standard, every time, going forward.

**Breadcrumb as you work.** An Operational Efficiency rule. Drop breadcrumbs where each change settles, in the artifact's own location, throughout the session. The session close becomes the reconcile of late-settling items, not the first pass. This keeps closeout light by design.

**Pre-publish sweep gate.** An Expression Standards rule. Before presenting any outward-facing draft (email, article, social, landing copy), run the pre-publish sweep. The highest-stakes surfaces are the most common drift point, so the gate fires before the draft leaves your hands.

**Fact Ratified sweep.** A canonical-fact change discipline. When a product or surface fact changes (a name, a price, a change of availability), the change is not complete until a full grep for the old string has run and every downstream reference is reconciled or confirmed as intentional history. Ratification and the sweep are one unit of work. This is the fact face of Claim Integrity.

**Pending Plan status vocabulary updated.** The status set is now `proposed`, `approved`, `ready-for-execution`, `implemented`. See the next section for the full migration.

### 2. Status-ladder migration across planning surfaces

The Pending Plan status set advances one direction only: `proposed` (written and scoped, not approved), `approved` (direction approved, decisions locked), `ready-for-execution` (implementation plan written), `implemented` (shipped, log final). Regression means a rollback or a separate new plan.

The migration touches every live planning surface so nothing references a stale status name:

- Pending Plan Implementation Protocol
- Reconciliation Protocol
- Progress Update Protocol
- Batch Archival Protocol and the Batch Archival skill
- Capture Classify Route Protocol
- The PendingPlan object template

**Archival is now a lifecycle event, not a status value.** A plan reaches `implemented` and stays there. Archiving it later is operational closure, a move to the Vault, not a status the plan carries. This removes the old confusion where archival looked like a terminal status competing with `implemented`.

### 3. Humor Codex graduates to seeded starter

The Humor Codex shipped as a placeholder. It now ships as a seeded starter, so the ecosystem arrives a little bit funny out of the box and the AI Interface can run real humor beats in its first session.

What it carries now:

- **The blend.** A default mix the AI Interface tunes over time.
- **The Jacket Layer.** Thirteen named jackets in three families. Each jacket is one trigger and one move, a named door the AI Interface steps through for a single beat.
  - **Wit** (five): Take the Hit, The Reactive Catch, The Escalating Runner, Plant and Detonate, Set Up the Other Voice.
  - **Wonder** (three): Cosmic Zoom-Out, Joy as Baseline, Guileless Over Sharp.
  - **Meta** (five): Name the Frame, Genre-Tag the Moment, The Charming Deflection, Make the Constraint the Feature, Earned Heart Under the Bit.
- **The density dial.** The blend is the mix, the density is the volume. Hold it steady through heavy execution where humor drift is most likely.
- **Rotation discipline.** The same door twice in a row reads as a tic. Different doors keep the room alive.
- **Seed and detonate.** Plant a vivid phrase early with no fanfare. Fire it later when the context rhymes.
- **A Make This Yours section.** The seeds are universal dry-wit moves built to be overwritten. Six prompts reshape the codex into your own comedic voice.

Personalizing the codex stays a named onboarding step. Session 3 (Codex Activation) points here for a first light pass. A deeper calibration lives in the Optional Path once you have felt the system run.

### 4. Autonomous Improvement Session menu deepens

The skill shipped with a 15-item menu inline in the SKILL.md. The menu now lives in a new `references/menu-catalog.md` and holds 36 items.

- **Tier 1 (8 items)** land edits directly. Wikilink integrity, index regeneration, anti-AI sweep on drafts, slug normalization, codices-index completeness, superseded-artifact sweep, runtime log rotation, skill mandatory-sections completeness.
- **Tier 2 (28 items)** run read-only scans and report for review. Inbox triage, stale drafts, link rot, memory and skill cross-reference health, breadcrumb propagation, implemented-plan archival candidates, status vocabulary conformance, hook coverage, dependency and CVE audit, and more.
- **Research rotation categories** in the log frontmatter cast a wide net for new improvement types every run.

The SKILL.md now loads the catalog at the eligibility step and keeps the per-item execution specs out of the parent file. Progressive disclosure keeps the workflow lean while the menu grows wide. Promotion of an accepted candidate edits the catalog, not the SKILL.md.

### 5. Two write-time hooks

Two PostToolUse hooks. One enforces the em dash expression standard at write time. One triggers index regeneration when skill or plan files change.

Both hooks are POSIX sh compatible. They are non-blocking: violations and regen events produce log output, not hard errors. Exit code is always 0.

**`post-write-em-dash-check.sh`**

Fires after every Write or Edit to a `.md` file inside the configured vault root. Scans the file for em dash characters. When found, prints a warning with the line numbers and the count. Does not block the save.

The em dash rule in the Sovereign Ecosystem CLAUDE.md is absolute: no exceptions in any output, internal or external. This hook surfaces violations at write time rather than at review time.

**`post-write-index-regen.sh`**

Fires after every Write or Edit. Matches two path patterns:

- `Council Chamber/Skills/*/SKILL.md`: triggers Skills Index regen
- `Council Chamber/Pending Plans/*.md`: triggers Pending Plans Index regen

The Sovereign Ecosystem ships its indexes as static Markdown files with no bundled regen script. This hook ships with a configuration block: set `SKILLS_REGEN_CMD` and `PENDING_REGEN_CMD` to your own regen script invocations. Leave them empty and the hook still logs the trigger event without executing any regen command.

## How to Implement

### CLAUDE.md, codex and planning surfaces

1. Pull the updated `CLAUDE.md`. The five doctrine entries and the status vocabulary land in their named sections (Session Calibration, Operational Efficiency, Expression Standards, Approval Gate, Planning and Execution).

2. Pull the updated `Council Chamber/Codices/Humor Codex.md`. It replaces the placeholder. If you already personalized your humor codex, treat the seeded version as a reference and keep your own.

3. Pull the updated planning surfaces and the PendingPlan template. Then run a one-time grep across your own Pending Plans for any old status string and reconcile each to the new vocabulary. Archival becomes a Vault move after `implemented`, not a status.

4. Pull the Autonomous Improvement Session `references/menu-catalog.md` and the updated `SKILL.md`. Adapt the menu to your own vault during onboarding. The shipped catalog is generic.

### Hooks

1. The hook scripts are already present at `Council Chamber/scripts/hooks/`. No file copy needed if you are applying this update to an existing installation.

2. Make the scripts executable (Mac/Linux only):
   ```bash
   chmod +x "Council Chamber/scripts/hooks/post-write-em-dash-check.sh"
   chmod +x "Council Chamber/scripts/hooks/post-write-index-regen.sh"
   ```

3. Set the `SOVEREIGN_VAULT_ROOT` environment variable, or edit the `VAULT_ROOT` line at the top of each script directly. The variable controls which files the em dash hook inspects and where the index-regen hook writes its log.

4. If you have index regen scripts, set `SKILLS_REGEN_CMD` and `PENDING_REGEN_CMD` in `post-write-index-regen.sh`.

5. Register the hooks in `.claude/settings.json`. Add these entries inside the `"hooks"` object:

   ```json
   "PostToolUse": [
     {
       "matcher": "Write|Edit",
       "hooks": [
         {
           "type": "command",
           "command": "bash \"[your-vault-path]/Council Chamber/scripts/hooks/post-write-em-dash-check.sh\""
         },
         {
           "type": "command",
           "command": "bash \"[your-vault-path]/Council Chamber/scripts/hooks/post-write-index-regen.sh\""
         }
       ]
     }
   ]
   ```

   Replace `[your-vault-path]` with the absolute path to your vault root (e.g. `C:/Users/yourname/Documents/MyEcosystem` on Windows or `/Users/yourname/Documents/MyEcosystem` on Mac).

   If you already have a `PostToolUse` block from a prior update, merge the two new hook entries into the existing matcher list rather than creating a second `PostToolUse` block.

6. Restart Claude Code for hook registration to take effect.

## Path Parameterization

Both hooks resolve the vault root via a `VAULT_ROOT` variable at the top of the script. No absolute path is hardcoded. The recommended pattern is an environment variable (`SOVEREIGN_VAULT_ROOT`) with a fallback to the in-script variable. Set the env var in your shell profile to avoid editing the scripts after each repo update.

## Em Dash Exemptions

The Sovereign Ecosystem CLAUDE.md declares the em dash rule absolute with no exceptions. This hook reflects that: it checks every `.md` write inside the vault root without any exemption list. The output string in the warning is a colon, not an em dash.

## Index Regen Decision

The Sovereign Ecosystem has no bundled regen scripts. The hook ships with the **configuration block** approach: two empty variables the Sovereign points at their own scripts. This keeps the hook portable across installations that do or do not automate index builds, and it logs trigger events even when regen commands are absent.

## Why These Land Together

The five clusters share one root. Each is a pattern that held in a working vault long enough to prove it deserved a durable home. That is the Flywheel Check in action: a pattern noticed, then upgraded to a canonical surface or an enforcement hook. Claim Integrity is the spine. Verify the thing where it is asserted, not where it is convenient to assume. The hooks are the same instinct in code: catch the drift at write time, not at review time.
